Why the palettes felt wrong

You were right not to like them. Clay is warm cream with a terracotta accent. That is the exact pair Taste bans as the "assistant palette", and Anthropic's own design guidance lists it first among the looks that read as AI-made. The other five palettes kept the same structure and only swapped the hue: tinted paper, a mid-strength accent, glass cards and monospace labels. So they inherited the same problem.

The new shortlist below comes from Taste's library of 56 palettes taken from studied sites. I paired a light and a dark version with the same accent hue and checked contrast on each: body text is at least 8:1 everywhere, and secondary text is at least 4.8:1.

Decided: Bottle and yellow by default, Switzer throughout

Bottle and yellow is the theme every visitor sees first. Light mode is a near-white page with bottle-green ink (#0D2A1C, 14:1) and one yellow note (#F6E016) on the main button, which carries green text. Links use the green ink, not the yellow, because yellow on white is unreadable. Dark mode turns the page bottle green (#10241A) with a softer yellow (#F4D96C). The other palettes stay available as themes in a Settings panel, described below.

Burnt sienna (a theme in Settings). The page is your beige (#F5F5DC) and buttons and links use the sienna (#A0522D). The vermilion (#E35336) only works as a colour for shapes, never for text: it reaches 3.4:1 on beige, and white text on it reaches 3.8:1, both under the 4.5:1 minimum. So it becomes the second accent for the 3D links and data packets; in the mock it is the short bar above each number. Sand (#F4A460) reads too faintly on beige (1.8:1), so it turns into the accent in dark mode, where it reaches 8.9:1. One honest flag: this is the same warm cream and terracotta family as Clay, which Taste's linter fails as the "assistant palette". It will cost one fail in phase 2 unless the beige moves toward stone. I can keep it and write the reason down, or try a cooler ground.

Burgundy, white and blue (a theme in Settings). White page, burgundy (#7B1E34) for the main button, blue (#1F4FD1) for links and the 3D. Two accents breaks Taste's "one accent" rule, but here each colour has one job, so it should land as a warning, not a fail. In dark mode the burgundy lifts to #D0607A and the blue to #86A8FF so both still read.

Switzer is the most Apple-like face on the list. The repo on GitHub is public, so its files can't be committed: the Next.js build would load it from Fontshare's servers (or a private store), not through next/font. This page inlines it at build time only.

Phases

0. Fix live

The eight live-site problems above, in the current codebase. Nothing visual changes.

Done when: canonical points to charanvelavan.com, the home page is under 3 MB, and Bird's AI shows its own text.

1. Choose

You pick a palette, a type system and the decisions listed below.

Done when: one palette and one type system are written down as tokens.

2. Prototype v5

Re-skin the prototype with Bottle and yellow and Switzer, and replace the current palette picker with a Settings panel: theme, light, dark or system, and Lite mode. Every theme is one set of CSS variables, so switching only changes those values. The 3D colours (sky, links, packets) come from the same variables. Remove mono, eyebrows, glass captions, numbering, the custom cursor and emoji. Fix touch targets, press states and reduced motion.

Done when: Taste's inspector shows 0 fails at 1440, 768 and 412px, and all phone targets are 44px.

3. Figma

Tokens as Figma variables, plus the home page and one case study on laptop and phone, in your file.

Done when: you sign off the frames.

4. Next.js build

Tokens in globals.css with Tailwind v4, the font through next/font, the 3D as a client-only component, GSAP through useGSAP, and content from projects.js (with the text fixes).

Done when: lint and build pass, Lighthouse scores 90+ on a phone, and Taste lint shows 0 fails.

5. Launch check

Taste inspector, Apple HIG checks (hig-doctor), a keyboard-only pass, reduced motion, a real test on your Nord 4, and the print or PDF view.

Done when: everything passes or each remaining warning has a written reason.
